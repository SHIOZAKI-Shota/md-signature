長期保存

dns、git-hosting、directory、pgp の公開鍵は検証のたびに取得します。署名者が鍵を削除すると古い署名は検証できなくなり、ドメインやアカウントが乗っ取られると第三者の鍵が公開されます。このページでは、数年後の検証に備えて文書に証拠を保持する方法を説明します。

このページの内容

2つの手段

ts は署名者の申告にすぎません。第三者の時刻認証局（TSA）による RFC 3161 タイムスタンプを tsa ブロックとして追記し、必要に応じて署名に用いた公開鍵を埋め込みます。署名ブロックの中にタイムスタンプを持たせる方式（tsa_token）は 0.1 で廃止しました。

手段 示すこと 付与の時点 指定方法
method: tsa それより前のチェーン全体（以前のタイムスタンプを含む）が、TSA の時刻に存在したこと 署名の直後、またはいつでも、何度でも。末尾に追記する mdsig sign --tsa
mdsig timestamp
tsaUrl timestampDocument
pubkey 署名に用いた公開鍵そのもの。鍵が削除された後も、その鍵で署名が成立することを確認できる 署名時のみ（ペイロード内） mdsig sign --embed-key
embedKey

スナップショットだけでは、その鍵が署名者のものだったことは示せません。tsa ブロックと併用すると、「この鍵による署名が、この時刻までに存在した」ことまでを示せます。

署名の時刻 T(k)

署名の時刻を証明したい署名者は、自分の署名ブロックの直後に tsa ブロックを追記します。mdsig sign --tsa と TypeScript の tsaUrl は、署名と同時にこれを行います。

  • ブロック k の時刻 T(k) は、k より後ろにある有効な tsa ブロックの genTime に誤差（accuracy、ない場合は 0）を加えた値のうち、最も早いものです。
  • tsa ブロックのスライスはブロック k を含むため、T(k) はブロック k がその時刻までに存在したことを示します。
  • 検証結果の表示、鍵のスナップショットの報告、署名欄は、すべて同じ T(k) を使用します。ts とは別の値として示します。
  • 後ろに有効な tsa ブロックがなければ、T(k) は定まりません。TSA 証明書のチェーンを検証できない tsa ブロックは時刻を与えません。

T(k) は検証者が信頼する TSA のルート証明書に依存し、実装によって結果が異なることがあります。本版は RFC 4998 のような更新の連鎖を検証しないため、時刻を長期にわたって主張する保管者は、トークンと検証の結果を別途保存してください。要求または検証に失敗した場合、--tsa は署名ブロックも追記しません（終了コード 3）。

タイムスタンプブロック（method: tsa）

署名者を持たないブロックで、それより前のチェーン全体がある時刻に存在したことを示します。TSA 証明書の失効やハッシュアルゴリズムの危殆化に備え、重ねて追記することでタイムスタンプを更新できます。考え方は RFC 4998 と同じです。

キー 内容
method alg method: tsa と alg: rfc3161 の組。一方だけを持つブロックは malformed。
signer TSA の http:// または https:// の URL。検証で認証されるのはトークンの TSA 証明書で、この値ではない。
hash 通常のブロックと同じく、スライスのダイジェスト。sha256 または sha512。
sig DER 形式の TimeStampResp。messageImprint は、署名対象ペイロードを hash と同じアルゴリズムでダイジェストした値。
v ts reason x_* v は 0.1。ts は生成者の申告。任意で reason と x_*。ほかのフィールドを含むブロックは malformed。

生成者の手順

  1. 署名対象ペイロードを hash と同じアルゴリズムでダイジェストし、messageImprint とする。certReq を TRUE に、ランダムな nonce を付与した TimeStampReq を TSA に送信する。
  2. 応答の TimeStampResp 全体を sig に格納する。接頭辞は gzip+base64: を推奨。展開後のサイズは 1 MB まで。

検証の手順（5.4 節の手順 4 以降に代えて）

  1. トークンをデコードできない malformed
  2. 応答ステータスが granted または grantedWithMods でない、または messageImprint のアルゴリズムと値がペイロードのダイジェストと一致しない invalid · bad-signature
  3. CMS 署名と TSA 証明書チェーンを検証できた。genTime と TSA の名前を報告する valid
  4. チェーンを、検証者のトラストストアに照らして検証できない unresolved · not-found

tsa ブロックは require を満たしません。署名ブロックのないファイルには追記できません。

公開鍵のスナップショット（pubkey）

dns、git-hosting、directory のブロックは、署名に用いた公開鍵を pubkey に埋め込めます（directory は既定で埋め込む）。pgp のブロックには埋め込めません。pubkey は署名者自身が書いた値で、偽造者も自身の鍵を埋め込めるため、公開中の鍵との照合を経なければ有効とはしません。

検証の結果

状況 結果
鍵種別が alg と一致しない、デコードできない、key_fp が pubkey のフィンガープリントと一致しない malformed
埋め込まれた鍵で sig が成立しない。鍵の取得より前に判定するため、オフラインでも確定する invalid · bad-signature
公開中の鍵に、埋め込まれた鍵と同じ鍵がある valid
取得には成功したが同じ鍵がない、または鍵が存在しない unresolved · key-not-published
ネットワークの障害で鍵を取得できない unresolved · network

key-not-published のブロックを、検証者は有効として提示してはなりません。報告できるのは、埋め込まれた鍵で署名が成立すること、および T(k) が定まる場合はその時刻までに署名が存在したことです。

TypeScript は signDocument の embedKey: true、Go は SignOptions.EmbedKey で指定します。デモとエディタでは、連署の追加画面の「公開鍵を埋め込む」で指定できます。

TSA のルート証明書

タイムスタンプの時刻を報告できるのは、TSA 証明書のチェーンを信頼するルート証明書まで検証できた場合のみです。信頼するルートは実装ごとに異なるため、同じトークンが一方の実装で検証でき、他方では検証できないことがあります。

実装 信頼するルート 追加・置換
Go（CLI、mdsig serve） OS のトラストストア --tsa-root <file>
TSAVerifyOptions.ExtraRoots
TypeScript（@mdsig/core） 同梱する公開 TSA のルート証明書。tsaRoots で置換、extraTsaRoots で追加する（DER、または PEM テキスト） tsaRoots
extraTsaRoots
デモ、エディタ 起動時に tsa-roots.json を読み込む。読み込めない場合はライブラリの同梱分 「TSA ルート証明書」欄で PEM／DER を追加（メモリ内のみ）

同梱するルートは、CCADB が公開する Microsoft のルート一覧で「Included」かつ「Time Stamping」用途のものに限ります。tsa-roots.json は GitHub Actions が毎月照合し、一覧から外れたルートの削除や新しいルートの追加を Pull Request で提案します。
