長期保存

dns、git-hosting、pgp の公開鍵は検証のたびに取得します。署名者が鍵を削除すると古い署名は検証できなくなり、ドメインやアカウントが乗っ取られると第三者の鍵が公開されます。このページでは、数年後の検証に備えて文書に証拠を保持する方法を説明します。

このページの内容

  1. 3つの手段
  2. 署名へのタイムスタンプ（tsa_token）
  3. タイムスタンプ専用ブロック（method: tsa）
  4. 公開鍵のスナップショット（pubkey）
  5. TSA のルート証明書

3つの手段

ts は署名者の申告にすぎません。第三者の時刻認証局（TSA）による RFC 3161 タイムスタンプと、署名に用いた公開鍵の埋め込みを組み合わせて使用します。

手段 示すこと 付与の時点 指定方法
tsa_token その署名が、TSA の時刻に存在したこと 署名時。tsa_url と tsa_token はペイロード外のため、仕様上は署名後にも付与できる mdsig sign --tsa
tsaUrl
method: tsa それより前のチェーン全体（以前のタイムスタンプを含む）が、TSA の時刻に存在したこと いつでも、何度でも。末尾に追記する mdsig timestamp
timestampDocument

スナップショットだけでは、その鍵が署名者のものだったことは示せません。タイムスタンプと併用すると、「この鍵による署名が、この時刻に存在した」ことまでを示せます。

署名へのタイムスタンプ（tsa_token）

署名ブロックに tsa_url と tsa_token を付与すると、その署名がある時刻に存在したことを TSA が証明します。証拠のチェーンは document → hash → sig → tsa_token です。

生成者の手順

  1. sig の base64 をデコードしたバイト列の SHA-256 を計算する。
  2. その値を messageImprint とし、certReq を TRUE に、ランダムな nonce を付与した TimeStampReq を tsa_url に送信する。
  3. DER 形式の TimeStampResp 全体を tsa_token に格納する。形式は gzip+base64: を推奨。

検証者の確認事項

  1. 応答ステータスが granted または grantedWithMods で、messageImprint が SHA-256(sig の生バイト列) と一致する。
  2. トークンの CMS 署名と TSA 証明書チェーンを、検証者が選択したトラストストアに照らして検証する。成功した場合に限り、genTime と TSA の名前を報告する。
  3. 展開後のサイズは 1 MB まで。tsa_token はペイロード外で第三者が差し替えられるため、上限を設ける。

CLI は mdsig sign --tsa で付与します（URL を省略すると http://ts.ssl.com）。チェーンを検証できないトークンでも署名自体の判定は変わりませんが、時刻は表示しません。

タイムスタンプ専用ブロック（method: tsa）

署名者を持たないブロックで、それより前のチェーン全体がある時刻に存在したことを示します。TSA 証明書の失効やハッシュアルゴリズムの危殆化に備え、重ねて追記することでタイムスタンプを更新できます。考え方は RFC 4998 と同じです。

キー 内容
method alg method: tsa と alg: rfc3161 の組。一方だけを持つブロックは malformed。
signer TSA の http:// または https:// の URL。検証で認証されるのはトークンの TSA 証明書で、この値ではない。
hash 通常のブロックと同じく、スライスのダイジェスト。sha256 または sha512。
sig DER 形式の TimeStampResp。messageImprint は、署名対象ペイロードを hash と同じアルゴリズムでダイジェストした値。
v ts reason x_* v は 0.0.2 以降。ts は生成者の申告。任意で reason と x_*。ほかのフィールドを含むブロックは malformed。

検証の手順（5.4 節の手順 4 以降に代えて）

  1. トークンをデコードできない malformed
  2. 応答ステータスが granted または grantedWithMods でない、または messageImprint のアルゴリズムと値がペイロードのダイジェストと一致しない invalid · bad-signature
  3. CMS 署名と TSA 証明書チェーンを検証できた。genTime と TSA の名前を報告する valid
  4. チェーンを、検証者のトラストストアに照らして検証できない unresolved · not-found

tsa ブロックは require を満たしません。署名ブロックのないファイルには追記できません。

公開鍵のスナップショット（pubkey）

dns と git-hosting のブロックは、署名に用いた公開鍵を pubkey に埋め込めます（v が 0.0.2 以降、指定した場合のみ）。pgp のブロックには埋め込めません。pubkey は署名者自身が書いた値で、偽造者も自身の鍵を埋め込めるため、公開中の鍵との照合を経なければ有効とはしません。

検証の結果

状況 結果
鍵種別が alg と一致しない、デコードできない、key_fp が pubkey のフィンガープリントと一致しない malformed
埋め込まれた鍵で sig が成立しない。鍵の取得より前に判定するため、オフラインでも確定する invalid · bad-signature
公開中の鍵に、埋め込まれた鍵と同じ鍵がある valid
取得には成功したが同じ鍵がない、または鍵が存在しない unresolved · key-not-published
ネットワークの障害で鍵を取得できない unresolved · network

key-not-published のブロックを、検証者は有効として提示してはなりません。報告できるのは、埋め込まれた鍵で署名が成立すること、およびタイムスタンプを検証できた場合はその時刻に署名が存在したことです。

TypeScript は signDocument の embedKey: true、Go は SignOptions.EmbedKey で指定します。デモとエディタでは、連署の追加画面の「公開鍵を埋め込む」で指定できます。

TSA のルート証明書

タイムスタンプの時刻を報告できるのは、TSA 証明書のチェーンを信頼するルート証明書まで検証できた場合のみです。信頼するルートは実装ごとに異なるため、同じトークンが一方の実装で検証でき、他方では検証できないことがあります。

実装 信頼するルート 追加・置換
Go（CLI、mdsig serve） OS のトラストストア --tsa-root <file>
TSAVerifyOptions.ExtraRoots
TypeScript（@md-signature/core） 同梱する公開 TSA のルート証明書。tsaRoots で置換、extraTsaRoots で追加する（DER、または PEM テキスト） tsaRoots
extraTsaRoots
デモ、エディタ 起動時に tsa-roots.json を読み込む。読み込めない場合はライブラリの同梱分 「TSA ルート証明書」欄で PEM／DER を追加（メモリ内のみ）

同梱するルートは、CCADB が公開する Microsoft のルート一覧で「Included」かつ「Time Stamping」用途のものに限ります。tsa-roots.json は GitHub Actions が毎月照合し、一覧から外れたルートの削除や新しいルートの追加を Pull Request で提案します。
