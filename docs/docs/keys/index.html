公開鍵の解決

method は、検証者が公開鍵を取得する場所を指定します。有効な署名が示すのは「解決した鍵の保持者が、このバイト列に署名した」という事実です。その鍵が誰に結び付くかは方式によって異なります。

方式と鍵の取得先

方式 鍵の取得先 結び付く対象
dns selector があれば <selector>._mdsig.<signer>、なければ _mdsig.<signer> の TXT レコード。値は v=mdsig1; k=ed25519; p=<base64>。レコードが複数あれば、いずれかで検証できれば有効（鍵のローテーション用）。ブラウザなどシステムのリゾルバを使用できない環境では DNS-over-HTTPS で取得する。 ドメインの運用者
git-hosting https://<signer>.keys（例：https://github.com/alice.keys）の ssh-ed25519 行。key_fp（SHA256:…）があればその鍵のみを使用する。sig はペイロードに対する生の Ed25519 署名で、ssh-keygen -Y sign の SSHSIG 形式は使用しない。 Git ホスティングサービスのアカウント
tofu ブロック内の pubkey: ed25519:<base64>。状態を保持する検証者は signer と pubkey の対応を記録し、同じ signer の鍵が変化すれば、利用者が新しい鍵を承認するまで invalid（key-changed）とする。 鍵そのもののみ。署名後に改変されていないことは示すが、署名者が誰であるかは示さない。
pgp fpr の鍵を、ローカルの鍵束、signer のドメインの WKD、検証者が設定した鍵サーバ（既定は keys.openpgp.org）の順に取得を試みる。鍵サーバは署名ブロックでは指定できない。署名は gpg でも作成できるため、スマートカード上の鍵も使用できる。 メールアドレス（WKD ではドメインの運用者、keys.openpgp.org では確認済みのアドレス）

dns、git-hosting、pgp（WKD・鍵サーバ）は検証時点の鍵を取得します。署名者が鍵を削除すると古い署名は検証できなくなり、ドメインやアカウントが乗っ取られると攻撃者の鍵が公開されます。どちらも文書だけでは検出できないため、長期の証拠にはタイムスタンプと公開鍵のスナップショットを併用します（「長期保存」を参照）。

パスキー（alg: webauthn-es256）

認証器は任意のデータには署名しません。生成者は challenge = SHA-256(payload) と rpId = rp_id を指定して navigator.credentials.get() を呼び出し、応答を3つのフィールドに格納します。公開鍵は tofu（pubkey: es256:…）または dns（k=es256）から取得します。

challenge = SHA-256(payload)
signed    = authenticatorData || SHA-256(clientDataJSON)
sig       = "base64:" DER(ECDSA-P256-SHA256(signed))

検証者の確認事項

  1. clientDataJSON の type が webauthn.get で、challenge が SHA-256(payload) の base64url と一致する。
  2. origin のホストが rp_id またはそのサブドメインで、localhost 以外は https である。
  3. authenticatorData の先頭32バイトが SHA-256(rp_id) と等しく、User Present フラグが立っている。
  4. 上の式の signed に対する ECDSA P-256 / SHA-256 署名が、候補の es256 鍵で検証できる。

仕様書 §4 公開鍵の解決方法

公開鍵の公開手順

検証者が鍵を取得できるよう、署名の前に方式ごとの公開先へ鍵を登録します。CLI の mdsig keygen は Ed25519 の鍵ペアと、DNS に登録する TXT レコードを出力します。

dns と git-hosting の署名では、--embed-key で署名に用いた鍵をブロックに埋め込めます。鍵を削除した後も、その鍵で署名が成立することを確認できます。詳しくは「長期保存」の「公開鍵のスナップショット」を参照してください。
