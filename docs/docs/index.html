ドキュメント

md-signature の形式と検証の規則を、主題ごとに1ページずつ解説します。規範となるのは仕様書で、本ページの解説と仕様書が異なる場合は仕様書が優先します。

形式の基本

  • 形式と署名の計算

    署名ブロックの構文、文書の正規化とハッシュチェーン、秘密鍵で署名する対象ペイロードの組み立て。

    v hash sig md-signature/v1

  • 公開鍵の解決

    署名者の公開鍵を、DNS、Git ホスティング、OpenPGP、ブロック内のどこから取得するか。パスキーによる署名。

    dns git-hosting pgp tofu

  • 検証手順と結果

    ブロックごとの検査手順、ステータスと code、CLI の終了コード、JSON 出力の読み方。

    valid invalid unresolved --json

運用のための機能

  • 連署ワークフロー

    最初の署名者が必要な連署を宣言する require。承認の段階（step）、M of N（any）、順番より前の署名の扱い（order）。

    require step any order

  • 長期保存

    鍵の削除や乗っ取りの後も証拠を保持するための、RFC 3161 タイムスタンプ、タイムスタンプ専用ブロック、公開鍵のスナップショット。

    tsa_token method: tsa pubkey

  • 拡張フィールド

    文書の一部への署名（scope）、添付ファイルの固定（resources）、有効期限（expires）、撤回リスト（revocation_url）。

    scope resources expires revocation_url

目的から探す

文書に署名して受け渡したい 導入 · 公開鍵の公開手順
承認の順序と人数を規定したい 連署ワークフロー
数年後も検証できる状態で保管したい 長期保存
一部の節だけに署名したい、画像も固定したい scope · resources
CI やフックで自動的に検証したい 検証手順と結果 · CI と AI エージェント
別の言語で実装したい 形式と署名の計算 · テストベクタ（examples/）
