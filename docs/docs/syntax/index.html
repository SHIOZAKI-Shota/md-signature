ブロックのフィールド

表は生成者が出力する順序です。検証者はどの順序でも受け付けます。未定義のキーは x_* を除き malformed です。

キー 要否 値
v必須0.1
method必須dns git-hosting pgp tofu directory tsa
signer必須方式ごとの正規の形（識別子の正規化）
selector条件付きdns のみ。_ で始めない
key_fp条件付きgit-hosting のみ。SHA256:…
fpr条件付きpgp では必須。大文字の16進数 40文字または64文字
pubkey条件付きtofu では必須、dns・git-hosting・directory では任意。ed25519:<b64> または es256:<b64>
rp_id条件付きalg: webauthn-es256 では必須。パスキーの RP ID
display_name任意表示名。64 コードポイントまで、申告
role任意[a-z0-9][a-z0-9._-]*
reason任意自由記述
ts必須YYYY-MM-DDTHH:MM:SSZ
expires任意YYYY-MM-DDTHH:MM:SSZ
scope任意リスト：1行に1つのセクション ID
require任意リスト：順序行、段階行、要件行
resources任意リスト：<ref> hash=sha256:<hex>
revocation_url任意https://…
x_*任意私的拡張。署名対象に含まれる
alg必須ed25519 webauthn-es256 openpgp rfc3161
hash必須sha256:<hex> sha512:<hex>
sig必須base64:…。tsa ブロックは gzip+base64:… も可
webauthn_authenticator_data
webauthn_client_data		条件付きalg: webauthn-es256 では必須、それ以外では不可。署名対象外

署名対象ペイロードに含まれないのは sig と webauthn_* だけです。tsa_url、tsa_token、keyserver は 0.1 にはなく、書くと malformed になります。

値の規則

  • 1行に1つの key: value。キーは英小文字で始まり、英小文字・数字・_ からなる。同じキーの重複は malformed。
  • 空行を含めない。開始行は厳密に <!-- md-signature、終了行は -->。
  • 値に -->、--!>、<!-- を含めない。-- だけなら使用できる。
  • 制御文字、書式文字（双方向制御文字、ゼロ幅文字、タグ文字）、U+2028／U+2029、非文字を含めない。
  • key: | の後に2スペース字下げの継続行を置くと折り返し値になる。2スペースより後の空白は値の一部。継続行の末尾に空白を置かない。
  • 値はすべて文字列。YAML のパーサで読み書きしない（v: 0.1 が数値に、ts が日時型になる）。
  • LF を含む値は折り返し形式で書く。76文字を超える sig などのバイナリ値は、76文字ごとに折り返す。
signer: xn--r8jz45g.example        # ok: "--" is allowed
reason: see --> below              # malformed
role: Lead Reviewer                # malformed: one lowercase word
v: "0.1"                           # unsupported-version: not YAML

リスト形式の行

scope、resources、require の値は、1行に1件の「対象 → 属性」の並びです。値が1行だけなら単純形式（scope: terms）でも書けます。

<target> [SP <name>[=<value>]]…
フィールド 対象 属性
scopeセクション ID（[a-z0-9-]+）なし
resources相対パス（パーセントエンコード）または https:// の URLhash=sha256:<hex>
require<method>:<signer|pattern>role= user_verified member_of= pubkey=
  • 行頭の空白は読み飛ばす。字下げは構造を持たない。
  • 対象と属性、属性どうしは、ちょうど1つのスペースで区切る。
  • 属性は 名前=値 または値のない 名前。名前と値は最初の = で分ける。値は空にできず、空白を含まない。
  • 未知の属性、属性の重複、値の有無の誤りは malformed（require の未知の属性だけは合意ステータス unsupported）。属性の順序は自由で、生成者は role、user_verified、member_of、pubkey の順に書く。
require: |
  order mode=guide
  step
    dns:example.com role=approver
  step any=1
    tofu:bob@laptop role=reviewer pubkey=ed25519:11qYAYKx…HURo=

require の属性とパターン

属性 dns directory pgp git-hosting tofu
role=✓✓✓✓✓
user_verified✓✓——pubkey= と併用
member_of=✓✓✓✓—
pubkey=————名指しの行

member_of= の値は dns:<domain>（DNS の名簿）か、ユーザ情報・フラグメント・443 以外のポートを持たない https:// の URL（署名済みの名簿）です。tofu の行には pubkey= を付けることを推奨します。

パターン 一致する署名者
dns:*すべての dns の署名者
dns:*.<d><d> の下位のドメイン。<d> 自身は含まない
directory:*@<d>
pgp:*@<d>		ドメイン部分が <d> と完全に一致するメールアドレス
directory:* pgp:*
git-hosting:*		その方式のすべての署名者

これ以外で * を含む対象は malformed です。パターンの行は宣言した署名者自身を数えず、order mode=strict の宣言には書けません。

本文に置くマーカー

マーカーとして扱うのは、コードフェンスの外にあり、行全体がマーカーの文字列と一致する行（末尾の空白は除く）だけです。

書き方 意味
<!-- mdsig:section <id> -->
<!-- /mdsig:section -->		部分署名のセクション。ID は [a-z0-9-]+、入れ子と重複は不可（「拡張フィールド」の scope）。
<!-- mdsig:signatures -->署名欄を描画する位置。1つだけ有効（「拡張フィールド」の署名欄）。
```mdsig-list署名済みリストの項目を入れるコードフェンス。1行目は type: revocation または type: members（「拡張フィールド」の署名済みリスト）。

本文がコードフェンスの途中で終わる文書には、生成者は署名しません。すべての署名ブロックがコードとして表示されてしまうためです。
