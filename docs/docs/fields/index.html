拡張フィールド

基本のフィールドに加えて、形式 0.1 は次の任意フィールドを規定します。いずれも署名対象ペイロードに含まれるため、署名後に変更すると署名が破壊されます。連署の宣言（require）は「連署ワークフロー」、タイムスタンプは「長期保存」で説明します。

部分署名（scope）

マーカで囲んだセクションのみに署名します。セクション外の注記や記入欄は、署名後も署名を破壊せずに編集できます。

セクションマーカ

  1. <!-- mdsig:section id --> と <!-- /mdsig:section --> の行で囲む。各マーカは単独で1行を占め、行頭に空白を置かない。
  2. ID は [a-z0-9-]+。入れ子と同じ ID の重複は不可で、開始マーカには終了マーカが必要。
  3. コードフェンスの中の行はマーカではない。フェンスの判定は仕様 5.5 節の行単位の走査に従うため、どの実装でも同じ結果になる。

検証

  1. scope はリスト形式で、1行に1つのセクション ID を書く（属性はない）。ハッシュの入力は、列挙した各セクションの normalize(section) を列挙順に連結したもの。
  2. マーカが規則に違反していれば malformed、列挙した ID が見つからなければ invalid（scope-missing）。
  3. 検証者は、有効と報告するすべての箇所で部分署名であることを表示する（例：valid (partial: terms, fees)）。

scope のないブロックは、セクションを含むスライス全体を対象とします。セクション外の編集後もチェーンを有効に保つには、後続の署名者全員が scope を使用する必要があります。scope を持つブロックは require を満たしません。

hash = H(normalize(terms) || normalize(fees))
mdsig sign sow.md -m tofu -s alice@laptop -k ~/.mdsig/alice --scope terms,fees

添付ファイルの固定（resources）

文書が参照するスクリーンショット、図、データファイル、URL を SHA-256 で固定します。本文だけでなく、参照先の差し替えも検出できます。

参照の書式

  • 各行は <ref> hash=sha256:<16進数>。ハッシュはファイルまたは HTTP 応答本文の正確なバイト列に対して計算する。sha256 以外は unsupported（unsupported-hash）。
  • ローカルのパスはパーセントデコードしてから使用する。空白は %20 で書く。%2F、%5C、%00、不正な UTF-8、絶対パス、\ や :（ドライブレター、代替データストリーム）、. や .. のセグメントを含む参照は malformed。ファイル名は NFC で書く。
  • ref は https:// の URL、または文書のディレクトリを基準とする相対パス。URL は書かれたとおりに使用する。

検証

状況 結果
ローカルのファイルが存在しない invalid · resource-missing
ハッシュが一致しない（ローカル、URL とも） invalid · resource-mismatch
URL を取得しない（既定） 未検査と報告する
URL を取得できない unresolved

URL を取得すると、文書が検証されていることが配信元に伝わります。このため URL は利用者が要求した場合のみ取得し、https:// に限り、応答は 50 MB まで、プライベートアドレスへの接続は拒否します。

--auto-resources は、コードフェンスの外で ![..](..) や <img src> が参照するローカル画像をすべて固定します。リモートの内容は CDN の再エンコードなどで変化しうるため、長期の証拠にはローカルのコピーを固定してください。

有効期限（expires）

署名の有効期限です。見積書の有効期間や、一定期間だけ有効な承認に使用します。

  • 形式は ts と同じ YYYY-MM-DDTHH:MM:SSZ。実在しない日時（2月30日、24時など）は malformed。
  • 検証者の時計で期限を過ぎていれば invalid（expired）。
  • 取引の申込の期限には使わない。期限を過ぎるとブロックは無効になり、期限内に成立した合意まで、後から検証すると無効に見えるため（「エージェント間の合意記録」を参照）。
  • CLI の --expires は日時のほか、現在からの期間（30d、12h）を受け付ける。
expires: 2027-03-31T23:59:59Z
mdsig sign quote.md -m git-hosting -s github.com/alice --expires 30d

撤回（revocation_url）

署名者は、自身の撤回リストの https:// URL を署名に含められます。リストは type: revocation の署名済みリストで、撤回した署名ごとに revoked: の行を持ちます。

リストを信頼する条件

  1. リストを文書として検証し、成功する。リストの形式は下の「署名済みリスト」の規則に従う。
  2. リストのチェーンに、撤回対象のブロックと同じ method と signer（tofu はさらに同じ pubkey）を持つ有効なブロックがある。
  3. リストの検証では、リスト内の revocation_url、リモートのリソース、require を評価しない（循環の防止）。

検証の結果

ブロックの識別子が、信頼したリストに含まれる invalid · revoked
リストを取得できない、または信頼できない unresolved
利用者が取得を無効にした（--no-revocation）、オフライン 撤回は未検査と報告する。これだけでは無効にしない 
mdsig revoke contract.md --list mdsig-revoked.md -m dns -s example.com -k ~/.mdsig/example

識別子は撤回対象ブロックの署名対象ペイロードの SHA-256 です。ECDSA や OpenPGP の署名は秘密鍵なしで別のバイト列に変形できるため、sig から計算すると撤回を回避されます。mdsig revoke は識別子を計算してリストに追記し、リストに署名し直します。

署名済みリスト

撤回リストと名簿は、共通の形式の署名済みリストです。md-signature 文書の本文に、情報文字列が mdsig-list のコードフェンスを1つだけ置き、その中に1行に1件ずつ項目を書きます。表示したときに項目が見え、箇条書きや引用の中に紛れることもありません。

type 項目 信頼する発行者
revocation revoked: sha256:<hex> 撤回対象のブロックと同じ署名者（tofu はさらに同じ pubkey）
members member: <method:signer> 名簿の URL のホストを署名者とする dns:<host>

リストを信頼する条件

  • フェンスの最初の行は type: <種類>。以降の行に前後の空白と空行を置かない。member: の値はパターンでない正規の識別子。
  • フェンスが0個または2個以上、フェンスが閉じていない、種類が期待と異なる、不正な行が1つでもある場合は信頼しない。
  • チェーンに、期待する発行者による scope なしの有効なブロックがあり、最後のブロックの後に未署名の内容がない。
  • リストの検証では、撤回、リソース、require を評価しない（循環の防止）。リストのブロックから TOFU の鍵を記録しない。

取得は https:// の単純な GET に限り、検証する文書の情報は送りません。サイズは 10 MB まで、キャッシュは1回の検証の間だけ保持します。検証者は少なくとも 10 万項目のリストを扱えます。

表示名と署名欄

署名ブロックは表示されないため、表示側が検証結果から署名欄を作ります。本文に表を書き込むことはしません。

display_name

  • 署名者が申告する表示名。64 コードポイントまでで、生成者は RFC 8266 の Nickname プロファイルで整えてから書き込む。
  • 誰の名前でも書けるため、表示する際は検証済みの署名者の識別子と並べ、「（申告）」と添える。表示名だけを示してはならない。

<!-- mdsig:signatures -->

  • 本文にこのマーカーの行を置くと、表示側はその位置に署名欄を描画できる。マーカーがなければ本文の後に置く。
  • 置けるのは1つ。2つ目以降とコードフェンスの中のマーカーは無視し、検証者は警告する。
  • マーカーは最初の署名の対象になるため、位置は最初の署名で固定される。後の署名者が決められるのは、自分の行の内容（display_name、role）だけ。

署名欄を本文の中に描画する場合も、同じ検証結果を本文が触れられない領域（本文の外側の UI）に必ず示します。署名欄は無害化した本文の DOM の外で作成します。本文には、署名欄に似せた偽の表を誰でも書けるためです。

mdsig sign po.md -m dns -s example.com --selector 2026 --display-name "Example Corp" -r seller
mdsig render po.md -o po.html

署名欄の各行は、番号、表示名（申告）、署名者、確認方法、役割、申告時刻、時刻証明 T(k)、利用者確認、状態です。合意が成立していなければ、next から作った未署名の行が続きます。mdsig render はこの形の HTML を出力し、ライブラリは signatureTable で行のデータを返します。

アルゴリズムと私的拡張

alg

alg は必須で、省略時の既定はありません。ed25519 は実装必須。webauthn-es256・openpgp・rfc3161 は検証の実装を推奨。ml-dsa-44・ml-dsa-65・slh-dsa-sha2-128s・ed25519+ml-dsa-65 は予約済み。未対応のアルゴリズムは unsupported として報告します。

x_*

x_ で始まるキーは自由に使用できます。意味は規定されませんが、署名対象ペイロードに含まれます。それ以外の未定義のキーを持つブロックは malformed（unknown-field）となるため、将来の拡張が理解されないまま受理されることはありません。
