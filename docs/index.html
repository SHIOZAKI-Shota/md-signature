md-signature の意義

文書と署名を1つのファイルにまとめると、AI を含む自動化の安全性、記録の持ち運び、長期の検証が同時に成り立ちます。

  1. 契約業務に非プロプライエタリ

    Markdown は、PDF のような独自形式と違い、誰でも読めるテキストです。署名に使用する鍵は手持ちの SSH 鍵や自分で生成した鍵で足り、有料の証明書や電子契約サービスの契約は不要です。

  2. 脱プラットフォーム・データの自己完結

    署名は文書の中にあります。サービスの解約や事業終了、アカウントの削除があっても、ファイルさえあれば検証を継続できます。仕様は CC0、実装はオープンソースです。

  3. 時刻の証明と長期の証拠性

    RFC 3161 のタイムスタンプで、その時点に署名が存在したことを第三者の時刻認証局（TSA）が証明します。署名者が申告する時刻と違い、あとから改変できません。将来 Ed25519 が危殆化した場合も、耐量子署名のアルゴリズムが規定されれば、その署名を追記してチェーン全体を保護できます。

  4. 発行元が署名した証明書

    大学や企業が、自組織のドメインの DNS に公開した鍵で修了証や在籍証明に署名できます。受け取った側は、その組織が発行したものかを自分で確認できます。Verifiable Credentials を簡素にした使い方です。

  5. 承認ワークフロー

    稟議、契約、仕様変更、リリース判定など、承認が必要な手順を文書だけで進められます。require に必要な承認者を宣言し、各担当者が順に連署します。CI やブランチ保護で mdsig verify を実行すれば、全員の署名がそろうまで次の工程に進みません。

  6. Git で扱える合意記録

    署名の追加はファイル末尾への追記なので、差分が読みやすく、誰がいつ何に署名したかを PR でレビューできます。履歴の書き換えも署名の検証で検出されます。

  7. AI エージェント指示書の改ざん防止

    CLAUDE.md や AGENTS.md に署名し、実行環境（フックや CI）が読み込み前に mdsig verify で照合します。PR や再配布の過程で書き換えられた指示書は、エージェントが読む前に拒否されます。ツールの出力や Web ページ経由の注入は対象外です。

  8. AI と人間の協調（Human-in-the-loop）

    AI が生成・修正した文書や設定に、責任者がパスキーや SSH 鍵で連署するまで、CI は適用を保留します。require に指定した連署がそろわない間、mdsig verify は終了コード 5 を返します。

  9. RAG・ナレッジベースの汚染対策

    取り込み処理で、承認者（role: approver）の有効な署名がある文書だけを索引に登録します。偽の文書や途中での改変は検知できます。承認者自身の判断の誤りまでは防げません。

  10. 添付ファイルまで含めた証跡

    スクリーンショットやデータファイル、リモートの画像をハッシュで固定します。本文だけでなく、参照先の差し替えも検知できます。

  11. 機密文書を外部に出さない

    検証も署名もブラウザ内またはローカルの CLI で完結し、文書をサーバへ送信しません。tofu 方式ならネットワーク接続なしでも検証できます。

  12. エージェント間の合意記録

    AI エージェントどうしの取引で、売り手が署名した条件に買い手が連署します。条件のハッシュは x402 などの支払いに結び付けられます。

電子署名としての法的な扱いは、使用する鍵、運用、適用される法令によって異なります。

仕組み

  1. 末尾に署名ブロックを追記

    署名は HTML コメントのため、GitHub や VS Code の表示には出ません。本文は一切変更しません。

  2. 連署は先行する署名ごと保護

    2人目の署名は、本文と1人目の署名をまとめて対象とします。途中を改変すると、それ以降の署名はすべて無効になります。

  3. 公開鍵は既存の公開先から取得

    GitHub に登録済みの SSH 鍵、自社ドメインの DNS TXT レコード、パスキーなど。検証のための新規アカウントは不要です。

<!-- md-signature
v: 0.1
method: git-hosting
signer: github.com/alice
key_fp: SHA256:Rx9i…
display_name: Alice
role: author
ts: 2026-11-16T09:00:00Z
require: |
  dns:example.com role=approver
alg: ed25519
hash: sha256:3a0d…
sig: base64:q1Xv…
-->

次の一歩

ブラウザで動作を確認し、仕様を読み、手元の環境に導入できます。

  • デモ

    署名済みの例文を改変して、検証結果の変化を確認します。鍵の生成や連署の追加もブラウザ内で試せます。

  • エディタ

    手元の Markdown ファイルを開き、署名と検証を行います。プレビューとフォルダ単位の操作に対応します。

  • ドキュメント

    署名ブロックの形式、公開鍵の解決、検証手順、連署ワークフロー、長期保存、エージェント間の合意記録を主題ごとに解説します。記法の早見表もあります。

  • 導入

    CLI のインストール、TypeScript と Go のライブラリ、検証サーバ、CI での利用方法。
